## 1. System Architecture (The Orchestration Graph)
The project uses **LangGraph** (`orchestration/graph.py`) to orchestrate a deterministic state machine.

### Node Execution Sequence
1.  **`validate_intake`**: Reads the `IntakeResult` generated by the intake extraction pipeline.
2.  **`retrieve_clauses`**: Queries the FAISS vector database to fetch relevant policy wordings and IRDAI regulations.
3.  **`call_policy_api` & `call_hospital_api`**: Mock APIs returning policy status, waiting periods, and hospital empanelment data.
4.  **`apply_rules_engine`**: The deterministic business logic engine (see *Rules Engine* below).
5.  **`llm_reasoning`**: Generates a natural-language explanation of the adjudication with strict recommend-only boundaries.
6.  **`citation_guard`**: Checks the LLM output for hallucinated citations against retrieved text (Guardrail #2), with parent-child section hierarchy resolution (e.g., subsection `3.1` grounded under `Section 3`).
7.  **`escalation_gate`**: Evaluates triggers (e.g., high-value claim > ₹5L, PED flags, non-network hospitals, fairness violations) to route for human-in-the-loop review.
8.  **`format_recommendation`**: Constructs the final audit record.

### Shared Pipeline State (`orchestration/state.py`)
All nodes read from and write to a `TypedDict` named `PipelineState`. Key properties:
*   **Inputs**: `intake_result`, `pre_auth_request` (Validated Pydantic model).
*   **Retrieval**: `retrieval_query`, `retrieved_clauses` (List of `RetrievedClause` objects).
*   **API Data**: `policy_status`, `waiting_period_info`, `sub_limit_balance`, `hospital_empanelment`.
*   **Adjudication**: `adjudication_result` (Output from the Rules Engine).
*   **Outputs**: `recommendation` (RECOMMEND_AUTHORISE, RECOMMEND_DENY, RECOMMEND_QUERY), `confidence`, `escalation_triggers` (List of strings), `needs_escalation` (bool).
*   **Metrics**: `node_latencies`, `total_latency`, `llm_token_count`, `llm_cost_inr`.

## 2. Pydantic Schemas (`schemas/pre_auth_request.py`)
The system strictly relies on strongly-typed Pydantic v2 models.
*   **Financials**: All currency is stored as Python `Decimal` instances via a custom `_INR` type alias (rounded to 2 decimal places) to prevent floating-point drift.
*   **Core Model**: `PreAuthRequest` encapsulates:
    *   `patient`: Patient demographics (`full_name`, `age`, `gender`, `policy_number`).
    *   `policy`: Coverage limits, plan type (`PlanType` enum: individual, family_floater, group, senior_citizen, critical_illness, top_up, super_top_up), co-pay %, waiting periods.
    *   `hospital`: Empanelment status (`cashless_network`, `non_network`), city, hospital name.
    *   `diagnosis`: ICD-10 codes, clinical description, `is_pre_existing` flag.
    *   `procedure`: CPT codes, description, admission type (`emergency`, `planned`, `day_care`, `maternity`).
    *   `cost_estimate`: Contains `line_items` (array) and `total_amount`. **Constraint**: `total_amount` must equal the sum of `line_items` (within a ₹1.00 tolerance).

## 3. The Rules Engine (`rules/engine.py`)
A deterministic rules evaluator that executes prior to LLM reasoning. **It always returns a `RECOMMEND_*` status (never auto-approves directly).**
Execution order (any step can short-circuit to `RECOMMEND_DENY`):
1.  **Policy Validity**: Rejects if expired or lapsed.
2.  **Waiting Period**: Rejects if claim falls within initial (30d), specific disease (24m), or PED (48m/12m) waiting periods.
3.  **Exclusions**: Filters out non-payable line items based on IRDAI guidelines (e.g., non-medical consumables, cosmetic treatments).
4.  **Sub-limits**: Caps room rent and applies proportionate deductions to surgeon/doctor fees, plus disease-specific sub-limits (e.g. Cataract, Joint Replacement).
5.  **Co-pay/Deductible**: Applies percentage deductions to the final payable amount.
6.  **Fairness Check**: Verifies that protected-proxy attributes (gender, location) weren't used to deny claims.

*Output*: An `AdjudicationResult` containing `total_claimed`, `total_approved`, `total_deducted`, a list of `Deduction` objects (mapped to specific clauses), and the final recommendation.

## 4. Retrieval & Vector Store (`retrieval/vector_store.py`)
*   **Technology**: FAISS (`IndexFlatIP` - Inner product on L2-normalized vectors for exact cosine similarity).
*   **Embedding Model**: `sentence-transformers/all-MiniLM-L6-v2` (384-dim, runs locally).
*   **Data Models**: `DocumentChunk` and `RetrievedClause`.
*   **Corpus**: 15 documents across `retrieval/corpus/`:
    *   8 Policy wordings (`individual_health_standard.txt`, `family_floater_plan.txt`, `group_corporate_plan.txt`, `senior_citizen_plan.txt`, `critical_illness_plan.txt`, `top_up_super_top_up.txt`, `cataract_procedure_guidelines.txt`, `cardiac_stemi_guidelines.txt`)
    *   4 Benefit tables (`copay_schedule.txt`, `disease_sublimits_schedule.txt`, `room_rent_schedule.txt`, `waiting_period_matrix.txt`)
    *   3 IRDAI circulars (`irdai_cashless_timeline_enforcement.txt`, `irdai_master_circular_health_2024.txt`, `irdai_non_payables_schedule.txt`)
*   **Index**: Pre-built at `retrieval/faiss_index/` (`index.faiss` + `metadata.json`).
*   **Provenance**: Every chunk tracks exact metadata (`source_file`, `section`, `circular_date`, `circular_number`) so the LLM can generate verifiable citations.
*   **Evaluation**: Contains an internal `evaluate_recall_at_k()` method to test whether governing clauses are accurately retrieved against a benchmark dataset.

## 5. Intake & Extraction Pipeline (`intake/`)
*   **Multi-Modal Handlers**: Processes Digital PDFs (`pypdf`), Scanned PDFs/Images (`pytesseract`), DOCX (`python-docx`), and JSON (`json_handler`).
*   **Structured Extractor (`intake/structured_extractor.py`)**:
    *   **Section-Scoped Cost Extraction**: Scopes line-item parsing specifically to the `ESTIMATED COST BREAKDOWN` section to prevent non-financial form fields (e.g. `Policy Number: POL-889169`, `Procedure Code: CPT-27447`, `Admission Date: 2026-08-31`) from being incorrectly added as financial line items.
    *   **Multi-Currency Support**: Recognizes currency prefixes including `INR`, `Rs`, `Rs.`, `₹`, and `$`.
    *   **Line-Bounded Extraction**: Uses explicit newline-terminating regex boundaries `(?:\r?\n|$)` for patient name, hospital name, city, diagnosis, and procedure to prevent greedy multi-line matches.
    *   **Plan Type Inference**: Supports all `PlanType` variants (`individual`, `family_floater`, `group`, `senior_citizen`, `critical_illness`, `top_up`, `super_top_up`).
    *   **Mathematical Reconciliation Safeguard**: Prevents negative adjustment amounts from causing Pydantic `ValidationError`s.
*   **Interactive Clarifier**: Generates formal IRDAI-compliant TPA query notices if required data is missing.
*   **Output**: `IntakeResult` (a wrapper containing the schema, confidence scores, and OCR quality metrics).

## 7. Evaluation Framework

### `scripts/evaluate_pipeline.py` — 9-Dimension Evaluation
Runs all golden test set cases through the full pipeline and scores:
1. **Extraction Accuracy** — Field-level precision/recall
2. **Retrieval Quality** — Checks clause retrieval
3. **Grounding Fidelity** — Hallucinated citation rate
4. **Decision Accuracy** — Confusion matrix (TP, TN, FP, FN) vs. ground truth
5. **Escalation Precision** — Escalation precision and recall
6. **Latency** — Mean, p50, p95, p99 per case
7. **Cost** — Token usage and INR per transaction
8. **Robustness** — Accuracy breakdown per adversarial subtype
9. **Fairness** — References the separate fairness script

Output: Console report + `data/evaluation_results.json`

### `scripts/evaluate_fairness.py` — Fairness/Bias Testing
For 20 happy-path cases, applies 4 perturbation types:
1. **Gender swap** — Male↔Female with matching names
2. **Name perturbation** — Cross-regional/cultural name swap
3. **City perturbation** — Different geographic location
4. **All combined** — All 3 together

Asserts that `recommendation` and `total_approved` remain identical across perturbations.
Output: Console report + `data/fairness_results.json`

## 8. Frontend Interface (`frontend/`)
A responsive React + Vite + TypeScript web application (`frontend/src/App.tsx`) with dark-mode glassmorphic styling:
*   **Multi-Modal Submission Modal**:
    *   **Free Text Note**: Paste doctor notes and clinical letters $\rightarrow$ routes to `/api/v1/preauth/text`.
    *   **JSON Payload**: Paste structured JSON request $\rightarrow$ routes to `/api/v1/preauth/process`.
    *   **File Upload**: Drag-and-drop or select PDF, DOCX, PNG, JPG $\rightarrow$ routes to `/api/v1/preauth/upload`.
*   **Interactive Review Dashboard**:
    *   Live queue with status tags (`APPROVED`, `ESCALATED`, `QUERY`, `DENIED`).
    *   Key claim summary statistics (Claim Amount, Policy Number, System Decision).
    *   **AI Reasoning Trace**: Rich markdown display of the full LLM clinical rationale, deductions, policy clauses, and citations.
    *   **Immutable Audit Log**: Step-by-step transaction logs from intake to hash chain verification.
    *   **Human Sign-Off Action**: Reviewer sign-off button for escalated/queried claims.
*   **Dev Server Proxy**: Configured in `vite.config.ts` to proxy `/api` calls directly to the FastAPI backend at `http://127.0.0.1:8000`.
